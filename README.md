# Training Simulator

VR-тренажёр на Unity 6 / URP. Игрок появляется в лобби, переходит в сцену тренировки
и проходит сценарий из трёх групп по три шага: подойти в зону, взять объект, выбрать
объект лучом, нажать кнопку интерфейса. Верные действия и нарушения отмечаются звуком
и статусом, в конце показывается экран итогов с рестартом и возвратом в лобби.

## Как запустить

Открыть `Assets/Scenes/Lobby.unity` и нажать Play (сцены уже в Build Settings: `Lobby`,
затем `Training`). Перемещение — телепортация стиком, взять или выбрать объект — grip,
интерфейс работает и лучом, и мышью.

## Архитектура

Слои разделены по ответственности, связи идут через события:

- **Interaction** — фиксируют факт взаимодействия и публикуют сигнал. Четыре типа:
  зона, захват, выбор лучом, кнопка UI. Верно это или нет, они не знают.
- **Content** — сценарий как ScriptableObject: группы → шаги → действия. Чистые данные,
  на объекты сцены ссылаются по строковому id.
- **Core** — `ScenarioRunner`: единственное место, где решается «верно / ошибка /
  нарушение порядка», ведутся статусы и собираются итоги.
- **Highlighting**, **Feedback**, **UI**, **App** — подсветка, звук, окна и переходы.

`ScenarioRunner` зависит только от интерфейсов (`IHighlightService`, `IFeedbackService`,
`IEventBus`) и данных, поэтому реализации подменяются в инспекторе без правок логики.
Событийность своя — `EventBus` на типизированных сигналах, без UnityEvent и сторонних
библиотек. Интерактивные объекты и UI про раннер не знают: события XRI (`selectEntered`,
`Button.onClick`) заворачиваются в свои сигналы на входе. DI-контейнеров нет,
`SimulationContext` — просто владелец шины в пределах сцены.

## Как закрыты требования

| Требование | Решение |
|---|---|
| 3 группы по 3 шага, в шаге 1+ действий | `ScenarioDefinition` (структура не ограничивает количество) |
| Типы действий | зона, захват, выбор лучом, кнопка UI |
| Нарушения | чужая зона, не тот объект, не та кнопка — шаг закрывается «с ошибкой» |
| Нарушение порядка | группа закрывается целиком, остаток шагов — «пропущен» |
| Отметка выполнения и звук | статус шага + тон «верно» / «нарушение» |
| Сообщение о порядке действий | брифинг и чек-лист на табло при старте группы |
| Итоги | список шагов со статусами, «Попытаться ещё» и «Возврат в лобби» |
| Подсветка | Quick Outline на объектах, `UnityEngine.UI.Outline` на кнопках |
| Перемещение | телепортация (провайдеры непрерывного движения выключены) |
| UI мышью и контроллерами | uGUI + XR UI Input Module, луч и мышь |
| Примитивы, без сторонних ассетов | кубы и цилиндры, материалы URP Lit, звук генерируется кодом |

## Структура

```
Assets/
  Scenes/            Lobby, Training
  Scripts/TrainingSimulator/
    Events/          IEventBus, EventBus, SimulationSignals
    Interaction/     Zone / Grab / PointerClick / UIButton + база и реестр id
    Content/         Scenario → Group → Step → Action (ScriptableObject)
    Runtime/         StepStatus, ScenarioResult
    Core/            SimulationContext, ScenarioRunner
    Highlighting/    IHighlightService + Quick Outline
    Feedback/        IFeedbackService + звук
    UI/              GroupBriefingView, ResultsView
    App/             SceneFlow, LobbyMenu
  Prefabs/           Rig, Environment, Interactables, UI
  Materials/         M_*
  ScriptableObjects/ Scenario_AirportSecurity
```

## Сценарий «Аэропорт: служба досмотра»

| Группа | Шаги |
|---|---|
| Проверка документов | зона стойки → взять паспорт → «Документ действителен» |
| Досмотр багажа | зона ленты → выбрать лучом красную сумку → «На ручной досмотр» |
| Посадка на рейс | зона выхода → взять талон и отсканировать → «Открыть проход» |

Ловушки: служебная зона, «чистые» сумки, кнопки отказа. Объекты других групп тоже
считаются посторонними.

## Как добавить шаг

1. Положить в сцену префаб из `Prefabs/Interactables` и задать ему `Id`.
2. Дописать шаг в ассете сценария, указав тот же id в `targetId`.

Больше связывать нечего: объект находится по id через `InteractableRegistry`, а
подсветка, звук и UI подключены через шину.

## Что стоит знать

- Quick Outline под URP работает, хотя шейдеры писаны под Built-in RP. Если обводка
  пропадёт после смены настроек рендера, меняется только реализация `IHighlightService`.
- Отметки в чек-листе — `●`, `×`, `—`, `○`: символов `✔` и `✖` в LiberationSans нет.
- Корень `UI_ResultsScreen` должен стоять в нуле — `LazyFollow` задаёт локальную позицию.
- Зоны лежат на слое Ignore Raycast, телепорт-якорь висит на дочернем диске, иначе луч
  телепорта упирается в триггер зоны.
- Правка скриптов во время Play Mode перезагружает сборку и обнуляет несериализуемое
  состояние. Контекст и подписки восстанавливаются сами, прогон начинается заново с
  предупреждением в консоли; для тестов в шлеме лучше выбрать в Preferences
  «Script Changes While Playing → Recompile After Finished Playing».
- `ScenarioRunner.logInteractions` пишет в консоль каждое действие и вердикт по нему.
